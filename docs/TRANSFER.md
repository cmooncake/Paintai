# 画师数据迁移

左侧「数据迁移」提供按画师导出和导入，无需模型服务在线。

## 从旧电脑迁移

1. 等待画师当前任务结束，在左侧选择小笑。
2. 打开「数据迁移」，点击「下载迁移包」，保存 ZIP。
3. 在另一台电脑拉取包含此功能的代码、安装依赖并启动前后端。没有模型时可以按 [WEB.md](WEB.md) 用 `scripts/start-web.ps1 -Offline` 启动。
4. 打开新电脑网页的「数据迁移」，选择 ZIP，点击「导入并恢复」。空白画室同样提供此入口。
5. 导入成功后自动选择恢复的画师；到「作品库」「学习」「LoRA 实验」查看作品、课程进度、记忆与实验对照。继续创作前另外配置模型。

**Git 拉取不等于数据恢复。迁移包需单独带到新电脑并导入，不自动提交进 Git。**

## 包含与排除

包含画师资料、长期目标、课程定义和学习轮次、作品及评价历史、创作记忆、蒸馏经验、成长实验、文字风格档案、已发布 LoRA 对照报告和生成图。图片字节及历史评分保持不变，模拟结果仍标为模拟结果；迁移不会重新评分或改变学习是否通过。

不包含 API 密钥、模型服务配置、底模或 LoRA 权重、参考原作、任务队列、训练缓存和未发布的训练目录。历史参考对照的文字结论保留，风格档案解除参考图关联；如需继续参考图生成或对照评价，请重新上传作品并生成风格档案。仅靠迁移包不能恢复 LoRA 推理或训练。

## 冲突与完整性

- v1 迁移包恢复原画师和作品标识符，不合并、不覆盖。同一画师或冲突记录已存在时返回冲突，原数据不变。相同名字但不同标识符的画师可共存。
- ZIP 文件及解压总量上限 256 MB，元数据上限 16 MB，最多 10000 个文件。
- 只接收固定版本 JSON 清单和清单明确关联的 PNG；校验归属、路径、SHA-256 与图片格式。不执行包内代码、不导入 SQL、不接收模型或任意文件。
- 校验完成后暂存图片，再在数据库事务中写入记录；普通失败会回滚并清理暂存文件。若机器在文件移动与数据库提交之间断电，可能留下孤立画师目录；此时再次导入会拒绝覆盖，需先核对并移走孤立目录。
- 当前为本机单用户功能，沿用 API 的本地访问边界。

## API

- `GET /api/v1/painters/{painter_id}/export`：下载 ZIP；画师有排队／运行任务时返回 409。
- `POST /api/v1/painters/import`：请求体为 ZIP 二进制（`Content-Type: application/zip`），不是 multipart。成功返回 201、画师资料及恢复数量；无效包 400、冲突 409、上传过大 413。

迁移包结构：`manifest.json` 存版本、经过清理的固定表记录、LoRA 报告及 SHA-256；`gallery/*.png` 与 `lora_reports/<report>/<arm>.png` 存生成图。导入后转为新电脑数据目录内的相对路径，网页通过现有 API 获取图片。
