# M0：创作闭环

当前范围：画师创建/列表、主题分析与构思、单张生图、六维视觉评价、作品入库/查询、失败后单独重新评价。课程、经验检索、存档和 Web 界面仍属于后续阶段。

## 运行

在仓库根目录按 README 安装。Windows 可直接用 `.venv\Scripts\paintai.exe`；其他环境激活虚拟环境后使用 `paintai`。也支持 `python -m paintai`。

```powershell
paintai --offline painter add demo --name "小画师" --style "水墨"
paintai --offline painter list
paintai --offline create "秋天的树林" --painter demo
paintai --offline gallery --painter demo --limit 10
paintai --offline show <作品ID> --painter demo
```

全局参数必须放在子命令之前。`--offline` 明确选择模拟后端；无配置时不会悄悄使用模拟模型。任一角色使用 mock，作品就标注为 `simulated: true`。离线图片是固定测试图案，评分固定为 5，不是艺术创作效果。

## 可替换配置

复制 `configs/api.example.toml` 到仓库根目录的 `paintai.toml`，分别填写三个角色的 `base_url`、`model` 和 `api_key_env`。构思需要文本模型；评价需要能读取图像的模型；生成需要兼容 Images API 的图像模型。

三个角色可以使用不同服务商、不同密钥，也可以都使用相同环境变量名。仅在本机设置配置中指定的环境变量；密钥不写入 TOML、作品记录或 Git。程序不自动加载 `.env` 文件。

本机免鉴权服务可设置 `auth="none"`（只允许 localhost / 127.0.0.1 / ::1）；默认 `auth="env"` 仍要求环境变量密钥。可直接参考 [本地小模型接入](LOCAL_MODEL.md)。

生图另支持 `provider="sd_cpp"`，直接调用本地 CPU 运行器，见 [本地真实生图](LOCAL_IMAGE.md)。参数放在 `local_image` 中，不使用 API 密钥。

```powershell
paintai --config paintai.toml painter add real_demo --name "真实画师" --style "水墨"
paintai --config paintai.toml create "秋天的树林" --painter real_demo
```

- `planner` / `critic`：使用 `POST {base_url}/chat/completions`。默认 `structured_output="json_schema"`；兼容服务不支持时可设置 `json_object` 或 `prompt`。三种模式均做本地 Pydantic 校验。
- `generator`：使用 `POST {base_url}/images/generations`；接收 `b64_json` 或 HTTPS 图片 URL，立即保存为 PNG。不会把 API Authorization 请求头发送到图片下载地址。
- `parameters`：支持 `temperature`、`max_completion_tokens`、`reasoning_effort`、`size`、`quality`、`output_format`、`response_format`、`style`；按服务商和角色支持情况配置。必需字段 `model`、`prompt`、`n` 由程序管理，每次仅生成 1 张。
- API base URL 包含 `/v1` 等服务商要求的路径前缀；允许 HTTPS 或本机 HTTP 服务。原生 Anthropic、ComfyUI 等非兼容协议尚无适配器，不能只修改 URL 就使用。
- 接口为 `Planner`、`Generator`、`Critic` Protocol；新增协议时在 `providers.py` 增加适配器及工厂路由，存储和 Agent 无需随之修改。
- `data_dir` 相对于配置文件目录；`--data-dir` 优先于 `PAINTAI_DATA_DIR`，后者优先于配置。`PAINTAI_CONFIG` 可设置默认配置路径。`--offline` 默认使用工作目录下的 `data/`，忽略模型配置。

接口依据：[Chat Completions 官方参考](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Images 官方参考](https://developers.openai.com/api/reference/resources/images/methods/generate)。模型支持的参数不同；GPT image 模型不应设置旧的 `response_format` 参数。示例故意不固定模型名称，账户可用性留给部署配置。

## 数据与失败恢复

`data/paintai.sqlite3` 保存画师档案、创作状态、构思、配置快照（仅环境变量名）、评价和评价尝试历史。图片保存在 `data/painters/<painter_id>/gallery/<作品ID>.png`，数据库内使用相对路径。所有作品查询要求画师 ID，禁止跨画师读取。M0 是本机 CLI，数据隔离不是多用户访问控制。

正常状态：`planning → generating → generated → evaluating → complete`。

- 构思或生图失败：记录 `creation_failed`，不伪造图片或评分。
- 评价失败：记录 `evaluation_failed`，保留已保存的图片及构思。
- API 没有自动重试；超时也不会自动再次生图。一次正常创作最多发起 3 个模型请求（构思、生图、评价），图片 URL 模式另有一次下载。
- 评价失败后可更换评价配置并执行以下命令，不会再次生图；已完成作品重复执行为幂等读取。

```powershell
paintai --config paintai.toml evaluate <作品ID> --painter real_demo
```

异常退出后的 `generated` / `evaluating` 记录也可以用 `evaluate` 恢复。若在供应商已生成图片但本地尚未保存时进程终止，M0 尚不能从远端恢复任务；需要人工检查，不能保证外部计费恰好一次。M0 按单进程使用设计，不要对同一作品并发调用 `evaluate`。

评价规则版本为 `m0-six-equal-v1`：六个维度均启用，范围 1–10，总分由本地等权平均计算。模型仅提交维度分、反馈与建议，不决定总分。评价会发送实际图片和主题/目标风格；不会把此前评分或创作轮次传给评价模型。后续课程阶段的维度开关、权重及成长实验另行设计。

## 测试与验收

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src tests
```

测试覆盖本地持久化、实例隔离、六维分数校验、配置切换、模拟 CLI、图片格式、API 请求结构、真实图片传入评价、超时/429、不泄漏鉴权、评价恢复和错误记录。HTTP 测试使用模拟传输，不访问真实模型。

全本地真实验收已完成，详见 [全本地闭环与验收记录](LOCAL_FULL.md)：新作品构思、生图、看图评价及保存均使用真实本地模型，`simulated=false`。云端服务仍待 API 配置后独立验收；链路运行成功不证明画师已具备成长能力，也不代表评分已校准。
